# לוח שיחות (call-board)

CRM לשיחות מכירה, עם עוזר שיחה מקשיב: לידים, תדריך לכל ליד, סטטוסים וסנכרון חי לכל הצוות, הקשבה לשיחה עם התנגדויות ושלבים בזמן אמת, וטופס סיכום.

**הריפו הזה מכיל קוד בלבד.** אין בו לידים, טלפונים או נתוני לקוחות. הנתונים יושבים ב-Supabase, מאחורי התחברות והרשאות לפי משתמש (Row Level Security), ומיובאים מתוך האתר על ידי מנהל.

| קובץ | מה |
|---|---|
| `index.html`, `app.js` | האתר (GitHub Pages) |
| `config.js` | כתובת הפרויקט ב-Supabase והמפתח הציבורי שלו. המפתח הזה נועד להיות גלוי, וההרשאות נקבעות בשרת |
| `schema.sql` | הטבלאות וכללי הגישה. מריצים פעם אחת בעורך ה-SQL של Supabase |
| `check_no_pii.mjs` | בדיקה לפני כל העלאה: עוצרת אם נמצא טלפון, מזהה מקום של גוגל או קישור לפוסט |

## הקמה
1. פרויקט חדש ב-Supabase, ואז מריצים את `schema.sql`.
2. **Authentication:** מכבים הרשמה ציבורית. ב-URL Configuration מגדירים את כתובת האתר כ-Site URL וכ-Redirect URL.
3. מזינים את הכתובת והמפתח הציבורי ב-`config.js`.
4. מזמינים משתמש (Authentication ← Users ← Invite), ומצרפים אותו לצוות:
   ```sql
   insert into members (user_id, email, role)
   select id, email, 'admin' from auth.users where email = '<email>';
   ```
   מנהל (`admin`) יכול לייבא נתונים, וחבר צוות (`member`) עובד על הלידים.
5. **ייבוא:** בכניסה הראשונה מנהל לוחץ "ייבוא נתונים (מנהל)" ובוחר קובץ JSON בצורה `{leads, scripts, calls}`.

## אבטחה
- **כניסה:** מייל וסיסמה לכל אדם. אין הרשמה עצמית. מי שלא נמצא בטבלת `members` לא רואה כלום.
- **אין מחיקה מהאתר:** אין אפשרות למחוק רשומות שיחה.
- **הגנות בדף:** הספרייה נטענת עם בדיקת שלמות (SRI), ויש Content-Security-Policy שמתיר חיבור רק ל-Supabase.
- **הקלטה:** התמלול נשאר בדפדפן ולא נשמר בשרת. נשמרים רק טופס הסיכום, הסטטוס וההערות.
